## 2. 理论详解：语言模型到底在干什么？

### 2.1 一句话版本

> 语言模型做且只做一件事：**给定前面已经出现的文字（上文），预测下一个字（token）是什么**。

你手机输入法的"联想"就是这样工作的：你打出"今天天"，它预测你要打"气"。

### 2.2 从"字"到"token"（记号）

计算机不认识汉字，只认识数字。所以我们把文本切成**一小段一小段**，每一段叫一个 **token（记号）**，每个 token 对应一个整数 id：

```
"猫会跑。"  → 分词（BPE 算法，第 10 课会讲）→  [猫, 会, 跑, 。]  →  ids: [1968, 294, 1950, ...]
```

一整张"token → id"的对照表叫**词表（vocabulary）**，大小记作 `vocab_size`。本教程用的词表有 6400 个 token（`vocab_size = 6400`）。

### 2.3 数学形式：链式法则

一个由 n 个 token 组成的句子 $x_1, x_2, \dots, x_n$，它出现的概率可以分解为"一个一个预测"的乘积：

$$
P(x_1, x_2, \dots, x_n) = \prod_{t=1}^{n} P(x_t \mid x_1, x_2, \dots, x_{t-1})
$$

读法：**"出现整句话"的概率 = "出现第一个词" × "看到第一个词后出现第二个词" × "看到前两个词后出现第三个词" × …**

这就是所谓的**自回归（autoregressive）**：模型把"生成"拆成一步步"接龙"。你给它前 $t-1$ 个 token，它输出第 $t$ 个 token 的条件概率分布——一个长度恰好为 `vocab_size` 的向量，每个分量是该 token 被预测的概率，所有分量之和为 1。

### 2.4 训练 = 让概率"猜得更准"

- **损失函数**：我们拿真实文本（"猫会跑。"）给模型，它会在每个位置输出一个预测分布；我们希望它对真实下一个 token 给的概率尽可能高。把"真实分布"和"模型预测分布"之间的差距量化，就是**交叉熵损失（cross-entropy loss）**，数值越小越好。
- **优化**：用梯度下降（AdamW 优化器，第 11 课实现）不断微调模型参数，让损失逐渐下降。
- 模型学到的"知识"全部藏在**参数**里（一堆数字），所以训练完我们保存参数文件（`.pth`）——这就是"模型权重"。

### 2.5 推理/生成 = 从分布里"挑"下一个词

训练完之后，生成新文本就是循环：预测下一个 token 的分布 → 按某种策略挑一个（最简单的策略是**贪心**：挑概率最大的，即 argmax）→ 拼到上文后面 → 继续预测下一个。

> 第 09 课会教你手写这个生成循环，包括温度、top-k、top-p 等调节策略。

### 2.6 本教程的全局地图

把上面的范式拆成零件，就是 14 课的全貌：

```
           配置(02) 归一化(03) 位置编码(04)
数据(10) → 注意力(05) 前馈(06) 残差块(07) → 模型主体(08) → 输出头+生成(09)
                              ↓
   预训练(11) → 指令微调(12) → HF转换(13) → 端到端测试(14)
```

每一课只引入**一个**新概念，并在上一课基础上叠加——这就是"一课一分支"的意义：每课都是一个能独立验收的里程碑。

## 3. 工程骨架：四个目录的分工

切到本分支后，看一下仓库根目录的结构：

```
README.md                    ← 教程首页（14 课课程表 + 快速开始）
requirements.txt             ← 依赖清单（torch / transformers / datasets）
.gitignore                   ← 忽略产物目录（out/、checkpoints/、*.pth 等）
verify.py                    ← 验收入口（"判卷机"）
minimind3/                   ← 你的手写实现（从空壳 __init__.py 开始，逐课填满）
verify/                      ← 验收检查（每课新增一个 NN_xxx.py）
tools/                       ← 工具（make_synthetic_data.py 生成数据、fetch_reference.sh 导出参考实现）
tutorial/                    ← 文档（00-DESIGN 总设计 + 每课 NN-xxx/README.md）
data/                        ← 合成数据（本课先由工具生成，第 10 课开始被数据集类使用）
```

| 目录 | 职责 | 你会怎么用它 |
|---|---|---|
| `minimind3/` | **实现**（模型、数据集、训练脚本） | 每一课往这里新增一个手写文件 |
| `verify/` | **验收**（每课一组自动检查） | 跑 `verify.py` 给你打分 |
| `tools/` | **工具**（数据生成、参考导出） | 生成合成数据、导出标准实现供对比 |
| `tutorial/` | **文档**（理论 + 任务 + 坑） | 跟随学习；每课一份 |

记住一个原则：**代码在 `minimind3/`，验收在 `verify/`，两者一一对应、互相独立**。verify 只读你的实现、跑断言，不修改你的代码。

## 4. 理论详解：为什么数据必须"合成"？

真实 LLM 训练要喂几 TB 的互联网文本（维基百科、新闻、书籍……）。本教程有三个硬约束：

1. **零下载**：不让你去 pull 几个 GB 的数据集（仓库里 minimind 用的真实 jsonl 有大约 3GB，不适合教程）；
2. **确定性**：验收要求"训练后 loss 必须下降""生成必须能背出事实"——如果数据随机性太大，机器判分会不稳定，今天绿明天红；
3. **小**：一个微型模型（隐藏层 96~128 维）根本学不会真实世界的复杂语料，但学一个"封闭小世界"绰绰有余。

所以第 01 课的工具 `tools/make_synthetic_data.py` 生成的是**封闭世界的合成语料**：

- 预训练数据：`{"text": "猫在花园里跑。"}` —— 用有限的**名词（猫/狗/鸟/鱼/马/牛）× 动词 × 地点 × 形容词**按模板拼句子，词表封闭（一共就那么些字词）；
- SFT 数据：`{"conversations": [{"role": "user", "content": "请用一个句子描述牛。"}, {"role": "assistant", "content": "牛吃草，能产奶。"}]}` —— 用一个固定的"事实表"生成问答对。

关键设计：**固定随机种子（--seed）**。同一份数据可以被无限复现，验收时再也不会出现"上次能过、这次过不了"的玄学。

> 自行探索：`python -m tools.make_synthetic_data --out data --num 300 --seed 0` 生成 300 条；换 `--seed 1` 对比，再换 `--num 1000`。看 `data/tiny_pretrain.jsonl` 和 `data/tiny_sft.jsonl` 的内容长什么样。

## 5. 理论详解：验收框架 verify.py 是怎么工作的？

### 5.1 设计哲学

"抄没抄对"这个问题，人类判卷会累死，所以本教程用**程序判卷**：每个检查是一个 Python 函数，里面写好断言（assert），断言通过就是 PASS，抛异常就是 FAIL。

### 5.2 工作机制（读一遍代码就懂）

1. 根目录 `verify.py` 扫描 `verify/` 目录下所有**以数字开头**的文件（`01_skeleton.py`、`02_config.py`……，按文件名排序保证执行顺序）；
2. 每个文件里有一个 `CHECKS = [(名称, 函数), ...]` 列表，由 `register("描述")` 装饰器自动收集；
3. 逐项执行：PASS 打绿勾，FAIL 打印异常信息并以非零退出码结束（`git` 等工具据此判定失败）；
4. 支持 `--fast` 参数：跳过耗时训练类检查（比如真正跑一个 epoch），日常快速复查用。

```bash
.venv/Scripts/python.exe verify.py          # 全量（约 1~3 分钟）
.venv/Scripts/python.exe verify.py --fast   # 跳过训练类（数秒）
```

本课的 5 项检查（见 `verify/01_skeleton.py`）：
- 01.1 骨架文件齐全（README / requirements / minimind3 包 / verify 包存在）；
- 01.2 合成预训练数据可生成且可复现（两次生成 md5 相同）；
- 01.3 SFT 数据 schema 正确（conversations 字段、role 合法）；
- 01.4 命令行可运行、教程文件体积 < 100KB；
- 01.5 验收框架自身能发现检查项（元测试：判卷机也在被验收）。

### 5.3 常见用法速查

```bash
# 只看失败项
.venv/Scripts/python.exe verify.py 2>&1 | grep FAIL
# 单独调试某课某检查（数字前缀文件不能点式 import，用 importlib）
.venv/Scripts/python.exe -c "import importlib; importlib.import_module('verify.05_attention')"
```

## 7. 对照标准实现（minimind）

本课没有模型代码，对照点是**数据格式的兼容性**：

| 数据 | minimind 标准实现 | minimind3（本教程） |
|---|---|---|
| 预训练 | `dataset/pretrain_t2t_mini.jsonl`，每行 `{"text": "…"}` | `data/tiny_pretrain.jsonl`，**完全相同的 schema** |
| SFT | `dataset/sft_t2t_mini.jsonl`，每行 `{"conversations": [{"role":…,"content":…}]}` | `data/tiny_sft.jsonl`，**完全相同的 schema** |

这意味着：你后面手写的 `PretrainDataset` / `SFTDataset`（第 10 课）既能读合成小数据，**也能无缝换成 minimind 的真实大数据**（把 `--data_path` 指过去即可）。
